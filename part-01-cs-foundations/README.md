# Part 1 — CS Foundations

The mental models you use every day, made explicit. Data structures, algorithms, complexity, operating systems, networking, concurrency primitives, and the discrete math that ties them together.

## Why this part exists

Most engineers learned these once, half-forgot them, then rediscovered them on a production incident. This part is the version you wish you'd had bookmarked.

## Chapters in this Part

1. **[Data structures you actually use](01-data-structures.md)** — Arrays, hash maps, trees, heaps, graphs: when each is the right tool and what it costs in space, time, and cache behavior.
2. **[Algorithms in working code](02-algorithms.md)** — Sorting, searching, traversal, dynamic programming through real problems, not contest puzzles.
3. **[Complexity analysis without hand-waving](03-complexity.md)** — Big O, average vs. worst case, amortized cost, and why "fast enough" is a measurement, not a guess.
4. **[The operating system from a programmer's seat](04-operating-systems.md)** — Processes, threads, scheduling, virtual memory, file systems, and the system calls that show up in your stack traces.
5. **[Networking up the stack](05-networking.md)** — IP, TCP, UDP, DNS, HTTP/2 and 3, TLS: what each layer is actually doing for your request.
6. **[Concurrency primitives](06-concurrency-primitives.md)** — Mutexes, semaphores, condition variables, channels, atomics: the building blocks under every async library you'll touch.
7. **[The discrete math you'll reach for](07-discrete-math.md)** — Sets, logic, combinatorics, graph theory, modular arithmetic, applied to problems engineers actually hit.
